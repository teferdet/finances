# Адмін-панель та управління групами

Адмін-панель (`app/handlers/admin.py`, `app/handlers/admin_groups.py`, `app/handlers/group_admin.py`) надає системним адміністраторам і власникам групових чатів інструменти управління, діагностичні звіти та можливості масової комунікації.

## Контроль доступу

### Системні адміністратори
Авторизація системного адміна суворо перевіряється через `_is_admin(user_id)`. Користувач є системним адміном, якщо:
1. Його ID знаходиться в масиві `admin_ids` у `settings.json`.
2. Або його ID динамічно присутній у масиві `admin_ids` в колекції `Settings` MongoDB (`_id: "admin_settings"`). Супер-адміни можуть надавати та відкликати доступ динамічно через `/admin`.

### Адміністратори груп
Дозволи адмінів груп валідуються локально через `is_chat_admin()` (`app/utils/chat_admin.py`), перевіряючи реальних власників та адміністраторів Telegram-чату без надання глобальних привілеїв бота.
- **Обробка анонімних адмінів**: Безпечно обробляє `GroupAnonymousBot` Telegram, пропонуючи анонімним адмінам переключити свій персональний профіль для налаштування групи.

## Дашборд системного адміна (`/admin`)

Виклик `/admin` відкриває інтерактивний inline-дашборд:

1. **Системна та групова статистика**
   - Інтегрується з `export_service.py` та `analytics_reporter.py`.
   - Відображає метрики: Загальна кількість користувачів, DAU, активні групи, спільноти, записи фіату в БД, помилки API за сьогодні, розмір сховища MongoDB.

2. **Управління парсером (`CentralParserService`)**
   - Запитує `ProblematicSources` для перевірки збоїв веб-скраперів або API (CoinMarketCap / Yahoo / fx-rate).
   - Дозволяє примусовий ручний цикл оновлення парсера або очищення логів помилок (`cb_parser_clear_errors`).

3. **Управління групами та спільнотами (`admin_groups.py`)**
   - Системні адміни можуть переглядати всі активні/неактивні Telegram-групи, перевіряти кількість учасників, зв'язувати чати з Bot API 10.2 Communities та перемикати feature-прапорці груп.

4. **Експорт даних**
   - Генерує та надсилає повні CSV-дампи колекцій `Users` та `Groups` (`cb_admin_export_users`, `cb_admin_export_groups`).

5. **Режим обслуговування**
   - Перемикає глобальний `maintenance_mode` в базі даних. Блокує звичайні команди користувачів при активації.

6. **Управління адмінами та розсилка**
   - Додавання/видалення динамічних admin ID через FSM (`AdminManageStates`).
   - Запуск масових розсилок (`/broadcast`).

## Веб-дашборд

Крім in-Telegram панелі `/admin`, проєкт включає повноцінний **веб-дашборд** у `dashboard/`. Він надає ті ж можливості моніторингу та конфігурації через браузерний інтерфейс, з додатковою візуалізацією даних (графіки, таблиці, статистика колекцій). Детальніше: [Дашборд](DASHBOARD.md).

## Система адміністрування груп (`/group_settings`, `/rate`, `/group_stats`)

Реальні адміністратори груп використовують `/group_settings` у своїх групах для налаштування:
- **Валюти прослуховування**: Вибір фіат, крипто та stock-кодів, які запускають автоконвертацію в текстових повідомленнях.
- **Цільові валюти**: Встановлення базових валют конвертації.
- **Перевизначення мови**: Зміна мови бота спеціально для цього групового чату.
- **Ephemeral UI**: Налаштування таймера автовидалення для меню-повідомлень через `ephemeral_service.py`.

## Система розсилки (`/broadcast`)

FSM-потік (`BroadcastStates`) для масових оголошень:
1. **Створення**: Введення HTML-форматованого повідомлення.
2. **Попередній перегляд**: Рендер чернетки з кнопками підтвердження.
3. **Виконання**: Розсилка через `_send_batched` (обмеження 25 повідомлень/сек для дотримання Telegram `FloodWait`), з фінальним звітом доставки.

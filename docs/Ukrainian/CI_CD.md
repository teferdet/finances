# CI/CD та автоматизація (v6.6.0+)

Репозиторій використовує GitHub Actions (`.github/workflows/`) для валідації коду, моніторингу здоров'я, перевірки локалей та автоматизованого деплою на Oracle VPS з сучасною Docker Compose архітектурою.

## Workflows

### 1. `ci.yml` (Якість коду)
**Тригери:** Push в `main`/`dev`, Pull Request в `main`.
- Клонує репозиторій.
- Налаштовує Python 3.12 та Node.js 20.
- Встановлює `ruff` для лінтингу Python та `eslint` для React дашборда.
- Запускає `ruff check app/` для дотримання стандартів Python.
- Запускає `npm run lint` у `dashboard/frontend` для перевірки React-коду.

### 2. `locales.yml` (Валідація перекладів)
**Тригери:** Push або Pull Request, що змінюють файли в `locales/**`.
- Перевіряє, що всі `.json` файли є синтаксично валідним JSON.
- Порівнює `en.json` (еталонний файл) з усіма іншими мовними файлами (`uk.json` тощо).
- Фейлить збірку, якщо будь-які ключі перекладу відсутні в цільових мовах.

### 3. `security.yml` (Сканування вразливостей)
**Тригери:** Push в `main`, за розкладом (понеділки о 09:00 UTC).
- Використовує `pip-audit` для сканування `requirements.txt` та `dashboard/requirements.txt` проти відомих CVE.
- Фейлить збірку, якщо критичні залежності скомпрометовані.

### 4. `health.yml` (Моніторинг сервера)
**Тригери:** За розкладом (кожні 30 хвилин).
- Підключається до production-сервера через SSH з `appleboy/ssh-action`.
- Запитує `docker` daemon для перевірки, що контейнери `finances-bot` та `finances-dashboard` працюють (`docker compose ps`).
- Виводить діагностичну інформацію (Пам'ять, CPU, Диск) та читає останні 30 рядків логів контейнера, якщо сервіс впав.

### 5. `deploy.yml` (Production-деплой)
**Тригери:** Push в `main`.
- **Конкурентність**: Гарантовано працює тільки один деплой одночасно.
- **Кроки**:
  1. Витягує останній код гілки `main` на цільовому сервері.
  2. Створює або оновлює `.env` файл зі змінних GitHub Secrets (`BOT_TOKEN`, `MONGO_URI`, `BOT_ADMIN_IDS` тощо).
  3. Перебудовує Docker-образи через `docker compose build --no-cache`.
  4. Перезапускає сервіси у фоні через `docker compose up -d`.
  5. Виконує health check (чекає 20с). Якщо бот або дашборд впав при запуску, автоматично виконує `git reset --hard` до попереднього робочого коміту та перезапускає контейнери, помічаючи деплой як невдалий.

### 6. `stale.yml`
**Тригери:** За розкладом (понеділки о 09:00 UTC).
- Автоматично керує GitHub Issues та Pull Requests через `actions/stale`. Позначає неактивні протягом 30 днів як `stale`, закриває після 14 днів. Дозволяє винятки для лейблів `pinned` або `security`.

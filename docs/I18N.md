# 🌐 Localization (i18n)

**TL;DR:** Finances uses a lightweight, custom-built JSON-based internationalization (i18n) engine located in `app/i18n.py`. It supports nested keys and runtime language switching.

## JSON Locale Structure
Translations are kept in `locales/` directory (e.g. `locales/en.json`). The engine uses dot-notation to parse nested keys.

Example `locales/en.json`:
```json
{
  "menu": {
    "welcome": "Hello, {name}!",
    "settings": "⚙️ Settings"
  },
  "errors": {
    "not_found": "Data not found."
  }
}
```

## Adding a New Language

1. **Copy**: Duplicate `locales/en.json` to `locales/YOUR_LANG_CODE.json` (e.g., `es.json`).
2. **Translate**: Translate the values (the right side) while keeping the keys exactly as they are. Keep placeholders like `{name}` unchanged.
3. **Register**: Add the new language code (`"es"`) to `supported_languages` in your `config/settings.json`.

## Usage in Handlers

The `I18nMiddleware` injects the localized `i18n` instance into the handler data. You can access it in the handlers natively:

```python
from aiogram import types
from aiogram.types import Message

async def start_handler(message: Message, i18n: dict):
    # i18n parameter is a bound dictionary of the user's selected language
    # or the I18n class instance, depending on middleware implementation.
    # Typically used as:
    from app.i18n import get_i18n
    
    _i18n = get_i18n()
    # Resolve the key 'menu.welcome', formatting '{name}' with the user's name
    text = _i18n.get("menu.welcome", lang="en", name=message.from_user.first_name)
    await message.answer(text)
```

Refer to `config/settings.example.json` and the `locales/` folder. Usually includes: `en`, `uk`, `pl`, `cs`, `sk`, `de`, `fr`.

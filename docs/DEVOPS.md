# DevOps — Server Operations Guide

Complete operations reference for managing the **finances** bot on a production server.
This guide covers both **Modern (Docker)** architectures for versions 6.6.0+ and **Legacy (systemd)** architectures for older versions.

---
## 🐋 Part 1: Modern Deployments (v6.6.0+ with Docker Compose)

The application runs as a set of Docker containers defined in `docker-compose.yml`.

### 1.1 Service Management

| Command | Action |
|---|---|
| `docker compose up -d` | Start or restart the bot and dashboard |
| `docker compose stop` | Gracefully stop the services |
| `docker compose restart bot` | Restart only the bot container |
| `docker compose ps` | View current status of all containers |
| `docker compose down` | Stop and remove the containers |
| `docker compose build` | Rebuild images from source |

**Checking Container Health:**
```bash
docker inspect --format='{{json .State.Health}}' finances-bot | jq
```

### 1.2 Real-Time Logs

```bash
# Follow logs for all services in real time
docker compose logs -f

# Follow logs for just the bot
docker compose logs -f bot

# Follow logs for just the dashboard
docker compose logs -f dashboard

# View the last 100 lines and follow
docker compose logs --tail=100 -f bot
```

### 1.3 Resource Monitoring

```bash
# Live CPU, RAM, and Network usage (updates every second)
docker stats

# Get a one-time snapshot
docker stats --no-stream
```

### 1.4 Manual Deployment

```bash
APP_DIR="/home/ubuntu/finances"
cd "$APP_DIR"

git fetch origin main
git reset --hard origin/main

docker compose build --no-cache
docker compose up -d
docker compose ps
```

### 1.5 Useful One-Liners

```bash
# Completely wipe all Docker data (DANGER: Deletes all stopped containers, unused networks, and dangling images)
docker system prune -a --volumes

# Exec into the bot container for a Bash shell
docker exec -it finances-bot /bin/bash

# Check internal container settings.json (generated by entrypoint)
docker exec -it finances-bot cat /app/config/settings.json
```

## ⚙️ Part 2: Legacy Deployments (v6.5.0 and older with systemd)
#### 2.21 Service Management (systemd)

The bot runs as a systemd service named `finances-bot.service`.

### Core Commands

| Command | Action |
|---|---|
| `sudo systemctl start finances-bot` | Start the bot |
| `sudo systemctl stop finances-bot` | Stop the bot |
| `sudo systemctl restart finances-bot` | Restart the bot |
| `sudo systemctl status finances-bot` | View current service status |
| `sudo systemctl enable finances-bot` | Enable auto-start on server boot |
| `sudo systemctl disable finances-bot` | Disable auto-start |
| `sudo systemctl is-active finances-bot` | Check if running (`active` / `inactive`) |
| `sudo systemctl is-enabled finances-bot` | Check if auto-start is enabled |

### Detailed Status

```bash
sudo systemctl status finances-bot.service
```

Example output:
```
● finances-bot.service - Finances Telegram Bot
     Loaded: loaded (/etc/systemd/system/finances-bot.service; enabled)
     Active: active (running) since Mon 2026-07-20 03:00:00 UTC; 12h ago
   Main PID: 12345 (python)
      Tasks: 8 (limit: 4096)
     Memory: 124.5M
        CPU: 2min 15.320s
```

### Reload After Changing the Service Unit File

```bash
# Apply changes made to the .service file
sudo cp /home/ubuntu/finances/deploy/finances-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl restart finances-bot
```

### 2.3 File-Based Logs

The bot maintains its own log files via `RotatingFileHandler` in `/home/ubuntu/finances/logs/`.

| File | Contents | Rotation |
|---|---|---|
| `logs/bot.log` | All messages (DEBUG and above) | 10 MB × 5 files |
| `logs/errors.log` | ERROR and CRITICAL only | 5 MB × 3 files |
| `logs/d_admin.log` | Dynamic admin actions | 5 MB × 3 files |

### Commands for File Logs

```bash
# Follow the main log in real time
tail -f /home/ubuntu/finances/logs/bot.log

# Follow errors only
tail -f /home/ubuntu/finances/logs/errors.log

# View the last 50 lines
tail -n 50 /home/ubuntu/finances/logs/bot.log

# Follow multiple log files simultaneously
tail -f /home/ubuntu/finances/logs/bot.log \
        /home/ubuntu/finances/logs/errors.log

grep "2026-07-20" /home/ubuntu/finances/logs/errors.log

# List unique error sources with counts
grep "ERROR" /home/ubuntu/finances/logs/errors.log \
  | awk '{print $5}' | sort | uniq -c | sort -rn

# Show log file sizes
ls -lh /home/ubuntu/finances/logs/
du -sh /home/ubuntu/finances/logs/
```

### Rotated Log Archives


### 2.5 Backups

The bot automatically backs up MongoDB **every day at 03:00 UTC** into `/home/ubuntu/finances/backups/`.
Only the **7 most recent** backups are kept. Format: `backup_YYYYMMDD_HHMMSS.gz` (JSON + gzip, no `mongodump` required).

### Viewing Backups

```bash
# List all backups with size and date
ls -lh /home/ubuntu/finances/backups/

# Show the most recent backup
ls -t /home/ubuntu/finances/backups/backup_*.gz | head -1

# Total backup storage used
du -sh /home/ubuntu/finances/backups/
```

### Triggering a Manual Backup

```bash
cd /home/ubuntu/finances
source venv/bin/activate

python -c "
import asyncio
from app.config import get_settings
from app.services.backup import daily_backup
settings = get_settings()
asyncio.run(daily_backup(settings.database.mongo_uri))
"
```

### Inspecting a Backup File

```bash
# Preview backup metadata and document counts (no full extraction needed)
BACKUP=$(ls -t /home/ubuntu/finances/backups/backup_*.gz | head -1)
zcat "$BACKUP" | python3 -c "
import json, sys
data = json.load(sys.stdin)
meta = data.get('_meta', {})
print('Created :', meta.get('created_at'))
print('Database:', meta.get('database'))
print('Version :', meta.get('version'))
print()
print('Collections:')
for k, v in data.items():
    if not k.startswith('_'):
        print(f'  {k:25s} {len(v):>6} documents')
"

# Extract backup to a file for further inspection
BACKUP=$(ls -t /home/ubuntu/finances/backups/backup_*.gz | head -1)
zcat "$BACKUP" > /tmp/restore_check.json
wc -c /tmp/restore_check.json
```

### Restoring from a Backup

> [!WARNING]
> Restoration overwrites existing data in MongoDB. Only proceed if you are certain this is intentional.

```bash
# Extract the latest backup
BACKUP=$(ls -t /home/ubuntu/finances/backups/backup_*.gz | head -1)
echo "Restoring from: $BACKUP"
zcat "$BACKUP" > /tmp/restore.json

# Restore via Python
cd /home/ubuntu/finances
source venv/bin/activate
python3 -c "
import asyncio, json
from motor.motor_asyncio import AsyncIOMotorClient
from app.config import get_settings

async def restore(path):
    settings = get_settings()
    with open(path) as f:
        data = json.load(f)
    client = AsyncIOMotorClient(settings.database.mongo_uri)
    db = client[settings.database.mongo_database]
    for coll, docs in data.items():
        if coll.startswith('_') or not docs:
            continue
        await db[coll].delete_many({})
        await db[coll].insert_many(docs)
        print(f'  ✅ Restored {len(docs):>5} docs → {coll}')
    client.close()
    print('Done.')

asyncio.run(restore('/tmp/restore.json'))
"
```

### 2.6 Manual Deployment

> [!NOTE]
> Under normal circumstances, deployments are fully automated via GitHub Actions on every push to `main`. Manual deployment should only be used in emergencies.

```bash
APP_DIR="/home/ubuntu/finances"
VENV_DIR="$APP_DIR/venv"
cd "$APP_DIR"

# 1. Stop the bot
sudo systemctl stop finances-bot

# 2. Pull the latest code
git fetch origin main
git reset --hard origin/main
echo "✅ Updated to commit: $(git rev-parse --short HEAD)"

# 3. Update dependencies
"$VENV_DIR/bin/pip" install --upgrade pip setuptools wheel
"$VENV_DIR/bin/pip" install -r requirements.txt \
  --upgrade --upgrade-strategy only-if-needed
echo "✅ Dependencies updated"

# 4. Reload the systemd unit if it changed
sudo cp deploy/finances-bot.service /etc/systemd/system/finances-bot.service
sudo systemctl daemon-reload

# 5. Start the bot
sudo systemctl start finances-bot

# 6. Verify startup
sleep 3
sudo systemctl status finances-bot --no-pager
```

### Code-Only Update (no dependency changes)

```bash
cd /home/ubuntu/finances
sudo systemctl stop finances-bot
git pull origin main
sudo systemctl start finances-bot
```

### 2.7 Dependency Management

```bash
APP_DIR="/home/ubuntu/finances"
VENV_DIR="$APP_DIR/venv"
PIP="$VENV_DIR/bin/pip"
PYTHON="$VENV_DIR/bin/python"

# List all installed packages
"$PIP" list

# Show outdated packages
"$PIP" list --outdated

# Check for dependency conflicts
"$PIP" check

# Upgrade a single package
"$PIP" install aiogram --upgrade

# Force-reinstall all dependencies
"$PIP" install -r "$APP_DIR/requirements.txt" --force-reinstall

# Verify all critical imports work correctly
"$PYTHON" -c "
packages = [
    'aiogram', 'motor', 'pymongo', 'curl_cffi', 'aiohttp',
    'bs4', 'yfinance', 'pandas', 'psutil', 'cryptography',
]
for pkg in packages:
    try:
        m = __import__(pkg)
        v = getattr(m, '__version__', '?')
        print(f'  ✅ {pkg} ({v})')
    except ImportError as e:
        print(f'  ❌ {pkg} — {e}')
"

# Python version in the venv
"$PYTHON" --version

# Snapshot currently installed versions
"$PIP" freeze > /tmp/current_packages.txt
diff "$APP_DIR/requirements.txt" /tmp/current_packages.txt
```

### Recreate the venv from Scratch

```bash
APP_DIR="/home/ubuntu/finances"

rm -rf "$APP_DIR/venv"
python3 -m venv "$APP_DIR/venv"

"$APP_DIR/venv/bin/pip" install --upgrade pip setuptools wheel
"$APP_DIR/venv/bin/pip" install -r "$APP_DIR/requirements.txt"

sudo systemctl start finances-bot
```

### 2.8 Rollback & Recovery

### Automatic Rollback

GitHub Actions performs a rollback automatically if the bot fails to start after a deployment. No manual action is required.

### Manual Rollback to a Previous Commit

```bash
APP_DIR="/home/ubuntu/finances"
VENV_DIR="$APP_DIR/venv"
cd "$APP_DIR"

# Review recent commits
git log --oneline -10

# Roll back to a specific commit
COMMIT="abc1234"
sudo systemctl stop finances-bot
git reset --hard "$COMMIT"

# Restore dependencies for that commit
"$VENV_DIR/bin/pip" install -r requirements.txt \
  --upgrade --upgrade-strategy only-if-needed

sudo systemctl start finances-bot
echo "⏪ Rolled back to: $(git rev-parse --short HEAD)"
```

### Diagnosing a Failed Start

```bash
# Journal since the last service invocation
sudo journalctl -u finances-bot.service -b --no-pager | tail -50

# Run the bot directly in the foreground for full output
cd /home/ubuntu/finances
source venv/bin/activate
python -m app
```

### Portable Health-Check Script

Save as `/home/ubuntu/health.sh` and run with `bash /home/ubuntu/health.sh`:

```bash
#!/bin/bash
APP_DIR="/home/ubuntu/finances"
VENV="$APP_DIR/venv/bin/python"

echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"

# Service status
STATUS=$(sudo systemctl is-active finances-bot)
[ "$STATUS" = "active" ] \
  && echo "  ✅ Service : $STATUS" \
  || echo "  ❌ Service : $STATUS"

# Git commit
echo "  📦 Commit  : $(cd $APP_DIR && git log -1 --pretty=format:'%h — %s')"

# RAM
RAM=$(sudo systemctl show finances-bot --property=MemoryCurrent \
  | awk -F= '{printf "%.0f MB", $2/1024/1024}')
echo "  🧠 RAM     : $RAM"

# Disk
DISK=$(df -h / | awk 'NR==2{print $4}')
echo "  💾 Disk    : $DISK free"

# Latest backup

[ -n "$LATEST" ] \
  && echo "  💿 Backup  : $(basename $LATEST)" \
  || echo "  ⚠️  Backup  : none found"

# Last 5 errors
echo ""
echo "  📋 Last 5 errors:"
tail -5 $APP_DIR/logs/errors.log 2>/dev/null | sed 's/^/     /' \
  || echo "     (no errors log found)"

echo ""
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
```

# 🌐 Localization (i18n)

**TL;DR:** Finances uses a lightweight, custom-built JSON-based internationalization (i18n) engine located in `app/i18n.py`. It supports nested keys, runtime language switching, parameter formatting, and automatic English fallback.

## JSON Locale Structure
Translations are kept in the `locales/` directory. The engine uses dot-notation to parse nested keys.

Example `locales/en.json`:
```json
{
  "menu": {
    "welcome": "Hello, {name}!",
    "settings": "⚙️ Settings"
  },
  "errors": {
    "not_found": "Data not found."
  }
}
```

## Supported Languages

| Code | Language |
|---|---|
| `en` | English |
| `uk` | Ukrainian |
| `pl` | Polish |
| `cs` | Czech |
| `sk` | Slovak |
| `de` | German |
| `fr` | French |

The reference file is `locales/en.json` — all other languages must contain the same key structure.

## Adding a New Language

1. **Copy**: Duplicate `locales/en.json` to `locales/YOUR_LANG_CODE.json` (e.g., `es.json`).
2. **Translate**: Translate the values (the right side) while keeping the keys exactly as they are. Keep placeholders like `{name}` unchanged.
3. **Register**: Add the new language code (`"es"`) to `supported_languages` in your `config/settings.json`.
4. **Validate**: The CI workflow `locales.yml` automatically checks that all language files contain every key present in `en.json`.

## Usage in Handlers

The `I18nMiddleware` injects the localized `i18n` instance and `lang` string into handler data:

```python
from aiogram.types import Message
from app.i18n import I18n

async def start_handler(message: Message, i18n: I18n, lang: str):
    text = i18n.get("menu.welcome", lang, name=message.from_user.first_name)
    await message.answer(text)
```

### `I18n.get(key, lang, **kwargs)`
- Resolves dot-separated keys (e.g., `"menu.welcome"`)
- Applies `str.format()` with provided keyword arguments
- Falls back to English (`en`) if the key is missing in the target language
- Returns the raw key string if not found in any language

### `I18n.get_section(section, lang)`
- Returns an entire section as a dictionary (e.g., `i18n.get_section("menu", "uk")`)

## Middleware Pipeline

The `I18nMiddleware` (registered as an outer middleware on `message`, `callback_query`, `inline_query`, `my_chat_member`, and `chat_member` update types) resolves the user's language preference from:
1. User's database record (`Language` field)
2. Group settings override (for group chats)
3. Telegram client language code (`message.from_user.language_code`)
4. Default language from `settings.i18n.default_language` (fallback: `en`)
